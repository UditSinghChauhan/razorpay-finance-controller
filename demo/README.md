# `demo/` — product and demonstration fixtures

## What this directory is

This directory holds **hand-built product/demo fixtures**. They exist to drive
the ASSAY product surface — the exception and abstention queue, the Ambiguity
Certificate drill-down, the close report — so that the behaviour the system was
built to have can be *shown* rather than described.

`PROJECT_SPEC.md §10` specifies the demo against a named dataset,
`assay run --dataset demo-500`, and `§9` sizes it as a *"500-record demo
slice"* distinct from the *"10,000–20,000 per benchmark run"*. This directory is
that slice.

## What this directory is NOT

Five statements, each of which is a hard boundary rather than a caution:

1. **This is a product/demo fixture.** It was authored by hand to exercise a
   code path. It is not a sample, not a draw from any declared distribution, and
   not the output of a forward simulation.
2. **It is outside `bench/`.** Nothing here is a benchmark artifact. It is not
   generated by `assay generate`, it carries no seed from
   `PREREGISTRATION.md §6.1`'s split table, and it belongs to no split — not
   `train`, not `dev`, not `test`.
3. **It is never scored.** No `metrics.json` is produced from it, it enters no
   `RunKey`, and `assay bench` neither reads nor can reach it.
4. **It is not benchmark evidence.** No figure computed over this fixture is a
   measurement. It has no ground truth, no oracle labels, and no completeness
   gate has been run against it.
5. **It must never be used to support a benchmark claim.** Not a coverage
   figure, not an abstention rate, not a match rate, not a comparison between
   agents, and not a statement about ASSAY's accuracy, calibration or harm.
   `EVALUATION_SPEC.md §5.5` permits only numbers that exist in a committed run
   artifact; nothing here is one.

The reason for the separation is the reason the amendment register exists at
all. `PREREGISTRATION.md §10` **V35** discloses that the sealed TEST population
*"exercises none of the ambiguity, abstention or validation machinery this
benchmark exists to compare"* — on all fifty scored units, `truly_ambiguous`,
`abstentions` and `probes_spent` are `0`. V35 also records that regenerating the
corpus so that ambiguity appears would be a change made **in response to a
measured result**, which `DECISION_BRIEF.md §L.4` forbids outright.

This fixture is the other route, and it is the one the frozen text already
provides for: a demo dataset, built for demonstration, kept entirely outside the
measured corpus, and carrying no evidential weight whatsoever. Building it
changes no benchmark artifact, no seed, no threshold, no metric definition and
no sealed result. Benchmark **v1.0.13** and the signed tag `bench-v1.0.13` are
untouched.

## `demo-500/`

`observations.jsonl` — one serialized `Observation` per line, in the shape
`packages/domain`'s `ObservationSchema` parses and
`apps/cli`'s `loadObservations` reads.

Its purpose is `PROJECT_SPEC.md §10` step 2, *"Step 2 is the demo. Everything
else is support."*: a settlement of ₹1,00,000 that is reconciled to a bank
credit through real bank-side evidence, and whose constituent recon lines carry
**no `settlement_id`** — so `AN1` cannot anchor them and stage `S2` must
enumerate the allocation for itself.

Two allocations survive `C1`–`C8`:

```
  {A, B, C}  = ₹50,000 + ₹30,000 + ₹20,000  = ₹1,00,000
  {D, E}     = ₹60,000 + ₹40,000            = ₹1,00,000
```

Both tie out exactly under `C6`, both settle inside `C4`'s T+1..T+7 window, and
both carry identical soft evidence — so `RECONCILIATION_SPEC.md §6`'s evidence
gap is far below `ε`. They differ in fee structure, so the two allocations post
materially different amounts to `1100_GATEWAY_RECEIVABLE`,
`5100_PG_FEE_EXPENSE` and `1300_GST_INPUT_CREDIT` — above `τ`.

`§6`'s ladder therefore reaches `AMBIGUOUS`, and ASSAY **abstains and mints an
Ambiguity Certificate** rather than committing a match it cannot justify. That
is the product.

The remaining rows are ordinary clean traffic — `AN1`-anchored settlements that
tie out, their matched bank credits, reference payments and orders, and a small
number of merchant-ledger-only entries — so that the close report and the
exception queue look like a real period rather than a single contrived case.

`apps/cli/tests/demo-fixture.test.ts` runs the real ASSAY agent over this file
and asserts the abstention. It asserts no rate, no accuracy and no comparison.
